# 闪耀优俊少女 · 种马搜索器

一个嵌入“吗哩吗哩工具箱”的 Chrome / Edge Manifest V3 扩展，用角色、因子星级和优先级筛选好友种马，并按综合匹配度排序。

扩展图标提供 16、32、48、128 像素四种标准尺寸，加载扩展后会显示在浏览器扩展管理界面中。

> [!IMPORTANT]
> 使用前必须在[吗哩吗哩工具箱](https://game.bilibili.com/tool/pd)手动完成 B 站登录。本扩展不会代填账号、密码或验证码，也不提供绕过登录的能力。

> [!NOTE]
> 这是非官方社区项目。B 站页面或接口更新后，扩展可能需要同步适配；请遵守游戏及网站的服务条款。

## 功能

- 按名称和初始星级检索、多选角色；不选角色时搜索全部角色。
- 任意拖动蓝、红、绿、白四类因子，设置颜色间优先顺序。
- 白因子独立拆分为剧本、技能、比赛三个目录，并支持名称检索和分批展开。
- 在技能目录中加入金技能虚拟项；选择金技能会自动查询、筛选和评分其对应的下位白技能因子。
- 粘贴自然语言要求，一键识别随机标点、连续因子名、繁中名称、缺失装饰符的正式名称以及家系/本体星级；多行 OCR 清单支持唯一的一字纠错并自动剔除噪声行。
- 每个具体因子同时设置家系合计至少 `1–9★`、本体至少 `0–3★` 和 P1 / P2 / P3 优先级；本体 `0★` 表示本体可以没有该因子。白因子还可设为“必需”。
- 将新因子默认放入 P1；可拖动紧凑因子行或使用下拉框调整优先级，再次点击目录中的同一因子即可取消。
- 一键重置全部已选因子，并可立即撤销；角色、颜色顺序和搜索范围不受影响。
- 合并默认推荐池、高优先级组合与单因子候选，去重后按综合匹配度从高到低展示。
- 可调搜索深度，并可过滤关注人数已满的玩家。

## 安装

本扩展通过 GitHub Releases 分发，不需要 Chrome 或 Edge 扩展商店。

### 准备工作

- Chrome 或 Microsoft Edge 的较新版本。
- 从 [GitHub Releases](https://github.com/yyahz/umamusume-seed-optimizer/releases/latest) 下载最新的 `umamusume-seed-optimizer-v版本号.zip`。
- 可正常访问吗哩吗哩工具箱的 B 站账号。

下载 ZIP 后，先将它完整解压到一个不会被随意删除的文件夹。不要直接在压缩包预览窗口中加载，也不要只解压某一个 JavaScript 文件。

### Chrome

1. 打开 `chrome://extensions`。
2. 打开页面右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择刚刚解压、并且直接包含 `manifest.json` 的目录。
5. 打开[吗哩吗哩工具箱](https://game.bilibili.com/tool/pd)，手动登录后刷新页面。
6. 点击页面右下角的“种马搜索器”。

### Edge

1. 打开 `edge://extensions`。
2. 打开左侧的“开发人员模式”。
3. 点击“加载解压缩的扩展”。
4. 选择刚刚解压、并且直接包含 `manifest.json` 的目录。
5. 打开[吗哩吗哩工具箱](https://game.bilibili.com/tool/pd)，手动登录后刷新页面。
6. 点击页面右下角的“种马搜索器”。

如果没有看到“加载已解压”按钮，请先确认开发者模式已经打开；浏览器受学校或公司策略管理时，该功能也可能被管理员禁用。

更新版本时，重新下载最新 ZIP，解压并替换原文件，然后在扩展管理页点击“重新加载”。角色、因子和优先级偏好通常仍会保存在浏览器的扩展本地存储中。

## 使用

1. 在“选择角色”中检索并多选目标角色；保留为空会搜索全部角色。
2. 拖动蓝、红、绿、白因子卡片，确定四种颜色的整体优先顺序。
3. 可以在“一键识别因子文本”中粘贴整段要求，检查预览后一次合并；也可以切换颜色及白因子子类手动选择。
4. 为每个已选因子分别设置家系合计星级、本体最低星级和 P1 / P2 / P3；白因子可在下拉框最后选择“必需”。
5. 选择每组候选页数及是否过滤满关注玩家，然后开始搜索；每页最多返回 20 位候选。
6. 根据总分、各颜色达标数和因子门槛提示比较结果。

颜色顺序权重为 `8 / 4 / 2 / 1`，颜色内部“必需”/ P1 / P2 / P3 权重为 `100 / 9 / 3 / 1`；“必需”仅对白因子开放。蓝、红因子以及设为“必需”的白因子均使用硬门槛：家系或本体任一不足，该具体因子得 0 分；完全达标得满分。其他因子仍可按接近门槛的程度获得部分分。每种颜色会先单独归一化，避免大量低优先因子仅凭数量压过高优先颜色。综合分仅表示当前偏好下的相对顺序，不代表游戏内继承概率或养成收益。

综合分相同时，会严格按用户拖动后的颜色顺序逐色比较：先比较该颜色的得分与达标数，再按 P 级权重比较实际家系星数和本体星数；只有四种颜色仍完全相同时，才比较总达标数、胜场数和好友 ID。因此调换颜色顺序也会改变同分候选的先后。

### 金技能映射

吗哩吗哩的因子目录只提供实际可能出现的白技能因子。扩展根据 [BWIKI 简中技能速查表](https://wiki.biligame.com/umamusume/简中技能速查表)中同一技能组的稀有度关系，在本地加入金色的虚拟选择项。例如选择`圆弧艺术家`，实际查询的是`弯道恢复○`；选择`先发制人`，实际查询的是`抢先`。目录、已选行和一键识别预览都会明确显示`金技能 → 下位白技能`。

映射快照日期为 2026-08-01，共收录 176 组关系。扩展启动时只展示“下位白技能仍存在于吗哩吗哩当前实时因子目录”的金技能，因此未实装、已改名或无法作为因子的项目不会出现。金技能和它的下位白技能是同一个筛选目标：在两种显示名称之间切换会保留已设置的家系星数、本体星数和优先级，不会重复计分或增加重复请求。

这份映射随扩展源码打包，不会在运行时访问 BWIKI，也不会将用户的选择或输入发送给 BWIKI。

### 繁中名称映射

扩展根据 BWIKI 的[因子一览](https://wiki.biligame.com/umamusume/因子一览)及[中日文对比表](https://wiki.biligame.com/umamusume/中日文对比表)，随包提供繁中因子名、繁中金技能名到简中正式名称的静态对照。当前快照日期为 2026-08-25，共包含 557 个唯一对照；启动时只启用“简中目标仍存在于吗哩吗哩实时目录或插件金技能目录”的项目。

这不是普通的繁简字符转换：不同服务器采用完全不同译名时也能正确对应，例如`夏日天空下的光暈 → 夏日光晕`。数据只在构建版本时从 BWIKI 更新，扩展运行时不会联网查询 BWIKI。

搜索深度按每个查询组计算：1 / 2 / 3 页分别最多读取 20 / 40 / 60 位候选。“查询组”包括默认推荐池、高优先组合以及最多 12 个单因子查询；不同组返回的重复玩家会按 ID 合并。页数越多通常覆盖更广，同时会增加请求量和等待时间。

## 一键识别因子文本

识别器完全在浏览器本地运行，并以当前页面实时返回的因子目录为准，不会把输入发送给第三方模型。可以直接粘贴类似内容：

```text
毅力9本体3，英里9本体3，夏日光晕，心头一击，位置感打基础点燃青春智，危险回避,URA剧本
```

预期识别结果包括：

- `毅力`：家系 9★、本体 3★。
- `英里`：家系 9★、本体 3★。
- `心头一击`补全为正式名称`心头一击♪啾`。
- `URA`补全为`URA剧本`，英文字母不区分大小写。
- `点燃青春智`匹配`点燃青春·智`。
- `点燃青春智`和`点燃青春智+`会严格区分；只有原文写出`+`时才匹配强化版。
- `位置感打基础点燃青春智`拆分为`位置感 / 打基础 / 点燃青春·智`。
- 多行输入会逐行解析，不再把相邻两行粘连；`医逃脱术`可剔除多余字并识别为`逃脱术`。
- 根据 BWIKI 的明确译名对照，繁中`夏日天空下的光暈`会映射为简中`夏日光晕`，繁中`太陽的睿智`会映射为简中`太阳的睿智`；预览会标注“繁中名称映射”。繁中名称存在唯一的一字 OCR 错误时也会先纠正再映射，例如`夏日天空下的光量 → 夏日天空下的光暈 → 夏日光晕`，并标注“繁中名称容错”。
- 多行 OCR 清单中的独立乱码、单字和无法匹配的整行会标为“已忽略”，不会阻止其他已识别因子导入。
- 一次识别出的技能因子达到 20 个时，会按照攻略原文顺序自动预排：前 10 个 P1、第 11–20 个 P2、第 21 个以后 P3；不足 20 个技能时不自动降级，全部沿用默认 P1。蓝、红、绿、剧本、比赛因子不参与这个数量和顺序计算。
- 未写星级的新因子默认家系 1★、本体 0★，并进入 P1。

识别后会先显示星级和自动 P 级预览，不会直接覆盖当前选择。已有因子保留当前 P 级；自动分级只作用于本次新增的技能因子。只有原文明示的家系或本体星级会覆盖对应字段。`本体0`是合法输入，表示不要求本体拥有该因子。歧义简称和超过 `1–9★ / 0–3★` 范围的数字会阻止导入；单行连续文本中的未知片段仍采用严格模式，多行清单中的未识别行则会明确列为已忽略。应用后可以立即撤销本次导入。

## 隐私与安全边界

- 扩展只在 `https://game.bilibili.com/tool/pd*` 页面运行，并向 `https://api.game.bilibili.com/*` 发出查询请求。
- 请求复用浏览器中已有的 B 站登录会话；扩展不会读取、保存、显示或导出 Cookie，也不会要求用户粘贴 Cookie。
- `chrome.storage.local` 仅保存角色 ID、因子选择与星级、颜色与 P 级顺序、搜索深度以及满关注过滤选项，方便下次打开时恢复偏好。
- 一键识别的原始文本、预览结果和撤销快照只保留在当前页面内存中，不写入扩展存储。
- 金技能和繁中名称映射均是随扩展打包的静态公开资料；运行时不会请求 BWIKI，也不会向其发送任何用户数据。
- 因子目录、角色目录和好友种马搜索均为只读用途；扩展不会关注玩家、修改账号资料或执行游戏内操作。
- 安装前可直接审阅全部源码；仓库不包含远程加载的扩展代码。

完整说明见[隐私政策](./PRIVACY.md)。

## 已知限制

- 搜索依赖当前登录状态、吗哩吗哩网页结构和公开网页接口；其中任一项变化都可能导致暂时不可用。
- 为控制请求量，自动发现最多使用当前最高优先的 12 个具体因子；所有已选因子仍会参与最终评分。
- 当前对单个好友种马排名；角色条件用于限定好友种马本体，尚未计算自有种马与七角色组合相性。
- 结果质量取决于接口当前可返回的数据、搜索深度和好友池，并不保证找到全服最优解。

## 开发与测试

本项目没有构建步骤。修改源码后，在仓库根目录运行：

```powershell
node --test
node --check ranking.js
node --check gold-skill-map.js
node --check page-bridge.js
node --check content.js
```

也可以直接在浏览器中打开 `tests/harness.html` 做静态界面检查。修改扩展后，需要在扩展管理页点击“重新加载”，再刷新吗哩吗哩页面。

## 项目结构

| 路径 | 作用 |
| --- | --- |
| `manifest.json` | Manifest V3 权限、站点范围与脚本入口 |
| `page-bridge.js` | 在页面上下文中调用官方网页接口 |
| `ranking.js` | 查询规划、因子整理与评分排序 |
| `gold-skill-map.js` | BWIKI 简中金技能到下位白技能的本地映射 |
| `traditional-name-map.js` | BWIKI 繁中因子/金技能名到简中正式名称的本地映射 |
| `factor-recognizer.js` | 本地文本规范化、因子分词、简称与星级识别 |
| `content.js` | 面板 UI、交互、偏好存储与搜索流程 |
| `tests/` | Node.js 单元测试与浏览器静态检查页 |
| `reverse-notes/` | 接口字段和行为的复核记录 |
| `scripts/build-release.ps1` | 生成并校验供 GitHub Releases 分发的安装 ZIP |
