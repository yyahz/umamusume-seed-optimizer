# 闪耀优俊少女 · 种马搜索器

一个嵌入“吗哩吗哩工具箱”的 Chrome / Edge / 360 浏览器 Manifest V3 扩展，用角色、因子星级和优先级筛选好友种马，并按综合匹配度排序。

仓库同时包含一个 [Android 轻量验证工程](./android-app/README.md)，用于在手机 WebView 中完成官方登录并复用同一套搜索逻辑。登录有效后 App 会从独立加载页直接进入全屏搜索器，不展示底层吗哩吗哩工具箱。当前 Android 工程属于测试版本，不替代已经发布的桌面浏览器扩展。

扩展图标提供 16、32、48、128 像素四种标准尺寸，加载扩展后会显示在浏览器扩展管理界面中。

> [!IMPORTANT]
> 使用前必须在[吗哩吗哩工具箱](https://game.bilibili.com/tool/pd)手动完成 B 站登录。本扩展不会代填账号、密码或验证码，也不提供绕过登录的能力。

> [!NOTE]
> 这是非官方社区项目。B 站页面或接口更新后，扩展可能需要同步适配；请遵守游戏及网站的服务条款。

## 功能

- 按名称和初始星级检索、多选角色；角色头像目录每页固定显示三行，可前后翻页，不选角色时搜索全部角色。
- 任意拖动蓝、红、绿、白四类因子，设置颜色间优先顺序。
- 白因子独立拆分为剧本、技能、比赛三个可选目录；三个子类的已选因子会始终合并显示，切换目录不会隐藏已选项。
- 在技能目录中加入金技能虚拟项；选择金技能会自动查询、筛选和评分其对应的下位白技能因子。
- 可选“智能识别攻略文本”模式，粘贴自然语言要求后识别随机标点、连续因子名、繁中名称、缺失装饰符的正式名称以及家系/本体星级；多行 OCR 清单支持受限纠错、相邻断行合并并自动剔除噪声行。不勾选时直接从目录逐项选择。
- 每个具体因子同时设置家系合计至少 `1–9★`、本体至少 `0–3★` 和必需 / 高 / 中 / 低优先级；本体 `0★` 表示本体可以没有该因子。蓝、红、绿、白四类因子均可设为“必需”。
- 将新因子默认放入高优先级；可拖动紧凑因子行或使用下拉框调整优先级，也可直接点击因子行左侧的删除按钮，无需返回上方目录取消。
- 一键重置全部已选因子，并可立即撤销；角色、颜色顺序和搜索范围不受影响。
- 合并默认推荐池、高优先级组合与单因子候选，去重后按综合匹配度从高到低展示。
- 推荐卡片会把全部蓝、红因子统一放在因子列表最前面：先显示已找到的目标蓝红因子，再补充候选家系中的其他蓝红因子及其家系/本体星级，之后才显示绿、白因子。
- 可选择并评分任意数量的绿因子；受吗哩吗哩搜索限制，每个接口查询组最多携带 3 个绿因子，其余高优先绿因子可由单因子发现查询补充候选，并全部继续参与最终评分。
- 可调搜索深度，并可过滤关注人数已满的玩家。

## 安装

本扩展同时通过 Chrome 应用商店、Microsoft Edge 加载项商店和 GitHub Releases 分发。Chrome / Edge 用户优先使用商店版以获得浏览器自动更新；360 浏览器或希望立即使用 GitHub 最新版本的用户可使用安装助手或手动安装。

### 推荐：从浏览器商店安装

- Chrome：[Chrome 应用商店商品页](https://chromewebstore.google.com/detail/jnnmlmfagfmihhghdfhimlahcmdkmien)
- Microsoft Edge：[Microsoft Edge 加载项商品页](https://microsoftedge.microsoft.com/addons/detail/kdhgepbpbhnngkdglhbpjeefadijeogk)

打开对应商品页并点击安装即可。商店版本通过审核后会由浏览器自动更新；由于商店审核需要时间，其版本号可能暂时落后于 [GitHub 最新版](https://github.com/yyahz/umamusume-seed-optimizer/releases/latest)。

### 推荐：使用 Windows 安装助手

普通用户推荐使用独立的[种马搜索器安装助手](https://github.com/yyahz/umamusume-seed-installer)。它会下载并校验本仓库的最新扩展包，把扩展安装到固定目录，并在更新失败时保留或恢复旧版本。

1. 前往[安装助手 Releases](https://github.com/yyahz/umamusume-seed-installer/releases)，下载文件名包含 `win-compact` 的最新版 EXE。
2. 双击运行，无需管理员权限，然后点击“安装 / 更新到最新版”。
3. 在助手中选择浏览器，点击“复制管理页地址”，到浏览器地址栏粘贴并回车。
4. 首次安装时开启开发者模式，返回助手点击“复制扩展目录”，再选择“加载已解压的扩展程序”。
5. 以后更新只需再次运行助手，然后在扩展管理页点击“重新加载”。360 安全浏览器如果没有“重新加载”按钮，可以先停用扩展再启用。

受浏览器安全限制，安装助手不能代替用户完成首次开发者模式确认，也不会读取浏览器 Cookie、账号或个人资料。其源码、隐私说明和安全边界均可在[安装助手仓库](https://github.com/yyahz/umamusume-seed-installer)审阅。

### 手动安装

开发者或不使用安装助手的用户，可以手动下载 ZIP：

- Chrome、Microsoft Edge、360 安全浏览器 16 或 360 极速浏览器 X 的较新版本。
- 从 [GitHub Releases](https://github.com/yyahz/umamusume-seed-optimizer/releases/latest) 下载最新的 `umamusume-seed-optimizer-v版本号.zip`。
- 可正常访问吗哩吗哩工具箱的 B 站账号。

下载 ZIP 后，先将它完整解压到一个不会被随意删除的文件夹。不要直接在压缩包预览窗口中加载，也不要只解压某一个 JavaScript 文件。

### Chrome

1. 打开 `chrome://extensions`。
2. 打开页面右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择刚刚解压、并且直接包含 `manifest.json` 的目录。
5. 打开[吗哩吗哩工具箱](https://game.bilibili.com/tool/pd)，手动登录后刷新页面。
6. 点击页面右下角的“种马搜索器”。

### Edge

1. 打开 `edge://extensions`。
2. 打开左侧的“开发人员模式”。
3. 点击“加载解压缩的扩展”。
4. 选择刚刚解压、并且直接包含 `manifest.json` 的目录。
5. 打开[吗哩吗哩工具箱](https://game.bilibili.com/tool/pd)，手动登录后刷新页面。
6. 点击页面右下角的“种马搜索器”。

### 360 安全浏览器 / 360 极速浏览器 X

1. 在地址栏打开 `chrome://extensions/`；如果该地址不可用，可点击右上角扩展按钮进入“扩展管理器”。
2. 打开扩展管理页右上角的“开发者模式”。部分版本需要刷新扩展管理页或重启浏览器后才显示开发者按钮。
3. 点击“加载已解压的扩展程序”，选择刚刚解压、并且直接包含 `manifest.json` 的目录。
4. 打开[吗哩吗哩工具箱](https://game.bilibili.com/tool/pd)，确认地址栏右侧的内核标志处于“极速模式”，然后手动登录并刷新页面。
5. 点击页面右下角的“种马搜索器”。

360 安全浏览器的“兼容模式”使用 IE 内核，无法运行 Chromium 扩展；必须切换为“极速模式”。建议使用最新正式版。当前版本已按 360 安全浏览器 16.1（Chromium 132 内核）验证扩展清单可加载，同时兼容官方使用 Chromium 122 内核的 360 极速浏览器 X。

如果没有看到“加载已解压”按钮，请先确认开发者模式已经打开；在 360 浏览器中还可尝试刷新扩展管理页或重启浏览器。浏览器受学校或公司策略管理时，该功能也可能被管理员禁用。

手动更新时，重新下载最新 ZIP，解压并替换原文件，然后在扩展管理页点击“重新加载”。使用安装助手时不需要自行替换文件。颜色顺序、搜索深度和过滤设置会长期保留；角色、因子、双星级和因子优先级只在当前浏览器会话内保留，刷新页面不会丢失，彻底退出浏览器后会自动清空。

## 使用

1. 在“选择角色”中检索、翻页并多选目标角色；每页显示两列三行，保留为空会搜索全部角色。
2. 拖动蓝、红、绿、白因子卡片，确定四种颜色的整体优先顺序。
3. 如需批量导入，在第 3 步勾选“智能识别攻略文本”，分多段粘贴要求；每段确认后加入待导入清单，最后一次应用全部内容。不勾选时切换颜色及白因子子类逐项选择；切换剧本、技能、比赛目录时，已选白因子会继续统一显示。
4. 为每个已选因子分别设置家系合计星级、本体最低星级和必需 / 高 / 中 / 低优先级；四类因子均可在下拉框最后选择“必需”。需要移除时可直接点击该因子行左侧的删除按钮。
5. 选择每组候选页数及是否过滤满关注玩家，然后开始搜索；每页最多返回 20 位候选。
6. 根据总分、各颜色达标数和因子门槛提示比较结果。

颜色顺序权重为 `8 / 4 / 2 / 1`，颜色内部必需 / 高 / 中 / 低权重为 `100 / 9 / 3 / 1`。蓝、红因子以及任意颜色中设为“必需”的因子均使用硬门槛：家系或本体任一不足，该具体因子得 0 分；完全达标得满分。只要设置了必需因子，排序会先保证“全部必需条件达标”的候选位于未全部达标者之前，再比较综合分和颜色顺序。其他绿、白因子仍可按接近门槛的程度获得部分分。每种颜色会先单独归一化，避免大量低优先因子仅凭数量压过高优先颜色。综合分仅表示当前偏好下的相对顺序，不代表游戏内继承概率或养成收益。

综合分相同时，会严格按用户拖动后的颜色顺序逐色比较：先比较该颜色的得分与达标数，再按高 / 中 / 低权重比较实际家系星数和本体星数；只有四种颜色仍完全相同时，才比较总达标数、胜场数和好友 ID。因此调换颜色顺序也会改变同分候选的先后。

### 金技能映射

吗哩吗哩的因子目录只提供实际可能出现的白技能因子。扩展根据 [BWIKI 简中技能速查表](https://wiki.biligame.com/umamusume/简中技能速查表)中同一技能组的稀有度关系，在本地加入金色的虚拟选择项。例如选择`圆弧艺术家`，实际查询的是`弯道恢复○`；选择`先发制人`，实际查询的是`抢先`。目录、已选行和一键识别预览都会明确显示`金技能 → 下位白技能`。

映射快照日期为 2026-08-01，共收录 176 组关系。扩展启动时只展示“下位白技能仍存在于吗哩吗哩当前实时因子目录”的金技能，因此未实装、已改名或无法作为因子的项目不会出现。金技能和它的下位白技能是同一个筛选目标：在两种显示名称之间切换会保留已设置的家系星数、本体星数和优先级，不会重复计分或增加重复请求。

这份映射随扩展源码打包，不会在运行时访问 BWIKI，也不会将用户的选择或输入发送给 BWIKI。

### 繁中名称映射

扩展根据 BWIKI 的[因子一览](https://wiki.biligame.com/umamusume/因子一览)及[中日文对比表](https://wiki.biligame.com/umamusume/中日文对比表)，随包提供繁中因子名、繁中金技能名到简中正式名称的静态对照。当前快照日期为 2026-08-25，共包含 557 个唯一对照；启动时只启用“简中目标仍存在于吗哩吗哩实时目录或插件金技能目录”的项目。

这不是普通的繁简字符转换：不同服务器采用完全不同译名时也能正确对应，例如`夏日天空下的光暈 → 夏日光晕`。数据只在构建版本时从 BWIKI 更新，扩展运行时不会联网查询 BWIKI。

逐项选择的因子搜索框也会同时匹配简中正式名称及对应繁中别名；输入完整繁中名称或其中一部分即可找到对应条目，搜索结果始终显示简中正式名称。逐项搜索不启用 OCR 模糊纠错，避免短关键词产生无关结果。

搜索深度按每个查询组计算：1 / 2 / 3 页分别最多读取 20 / 40 / 60 位候选。“查询组”包括默认推荐池、高优先组合以及最多 12 个单因子查询；不同组返回的重复玩家会按 ID 合并。页数越多通常覆盖更广，同时会增加请求量和等待时间。

## 智能识别攻略文本

识别器完全在浏览器本地运行，并以当前页面实时返回的因子目录为准，不会把输入发送给第三方模型。可以直接粘贴类似内容：

```text
毅力9本体3，英里9本体3，夏日光晕，心头一击，位置感打基础点燃青春智，危险回避,URA剧本
```

预期识别结果包括：

- `毅力`：家系 9★、本体 3★。
- `英里`：家系 9★、本体 3★。
- `心头一击`补全为正式名称`心头一击♪啾`。
- `URA`补全为`URA剧本`，英文字母不区分大小写。
- `点燃青春智`匹配`点燃青春·智`。
- `点燃青春智`和`点燃青春智+`会严格区分；只有原文写出`+`时才匹配强化版。
- `位置感打基础点燃青春智`拆分为`位置感 / 打基础 / 点燃青春·智`。
- 多行输入会逐行解析，不再把相邻两行粘连；`医逃脱术`可剔除多余字并识别为`逃脱术`。
- 被 OCR 压成一个超长段落的攻略清单，即使仍夹有少量杂乱换行，只要至少包含 80 个有效字符并先找到 8 个确定因子，就会自动进入长篇 OCR 模式：屏蔽`领跑推荐 / 领跑选学`等标题，在连续文本内部修复同长度错字及缺失的`○`，其余夹杂噪声汇总为已忽略内容。普通短文本仍保持严格匹配。
- 根据 BWIKI 的明确译名对照，繁中`夏日天空下的光暈`会映射为简中`夏日光晕`，繁中`太陽的睿智`会映射为简中`太阳的睿智`；预览会标注“繁中名称映射”。繁中名称存在唯一的一字 OCR 错误时也会先纠正再映射，例如`夏日天空下的光量 → 夏日天空下的光暈 → 夏日光晕`，并标注“繁中名称容错”。
- OCR 容错按正式名称长度限制错误比例：7 字以内最多 1 字，8–11 字最多 2 字，12–15 字最多 3 字，16 字以上最多 4 字，且不会超过名称长度的 25%。常规模式的多字容错只在完整独立行且最佳目标唯一时采用；长篇 OCR 模式还允许在连续文本内部恢复唯一的同长度错字。短文本、`◎ / +`仍保持严格匹配。
- 两字技能仍不开放普通错字猜测；仅允许将完整独立行的`沙浴。`安全恢复为`沙浴○`。原始标点会优先区分`马力全开`与金技能`马力全开！`。
- 当相邻两行各自均无法识别、合并后却能完整且唯一地对应一个长因子时，会自动修复 OCR 断行，例如`向着，更`加下一行`更远的地方.`可识别为`向着，更远的地方……`。
- 多行 OCR 清单中的独立乱码、单字和无法匹配的整行会标为“已忽略”，不会阻止其他已识别因子导入。
- 本轮待导入清单累计达到 20 个技能因子时，会按照各段加入的总顺序自动预排：前 10 个为高、第 11–20 个为中、第 21 个以后为低；累计不足 20 个技能时全部为高。蓝、红、绿、剧本、比赛因子不参与这个数量和顺序计算，跨段重复因子会合并。
- 未写星级的新因子默认家系 1★、本体 0★，并进入高优先级。

识别后会先显示星级和累计优先级预览，不会直接覆盖当前选择。可以继续粘贴下一段，也可以查看、清空待导入清单；点击“应用全部”后，各段会形成一个整体撤销点。已有因子保留当前手动优先级，自动分级只作用于本轮新增的技能因子。只有原文明示的家系或本体星级会覆盖对应字段。`本体0`是合法输入，表示不要求本体拥有该因子。歧义简称和超过 `1–9★ / 0–3★` 范围的数字会阻止加入；普通单行文本中的未知片段仍采用严格模式，达到长篇 OCR 条件的单行清单及多行清单则会明确列出被忽略内容。重置因子会同时清空识别预览和待导入清单；撤销导入或撤销重置不会恢复已经清空的待导入内容。

长攻略的识别结果使用固定高度的紧凑滚动清单，全部技能仍可直接查看。歧义、未识别内容和星级错误会合并到“需要修改”摘要，并在无法导入时获得键盘焦点；OCR 噪声会直接显示“忽略 N 处无效文字”，并完整列出本次被忽略的文字，重复因子等其他自动处理内容则另行简短汇总。

拖动浏览器窗口边缘时，面板宽度、字号和控件会按照窗口当前占屏幕的比例连续缩放，并根据面板自身宽度自动重排；较窄窗口使用紧凑单列布局，接近最大化时逐步扩大为多列布局。

## 隐私与安全边界

- 扩展只在 `https://game.bilibili.com/tool/pd*` 页面运行，并向 `https://api.game.bilibili.com/*` 发出查询请求。
- 请求复用浏览器中已有的 B 站登录会话；扩展不会读取、保存、显示或导出 Cookie，也不会要求用户粘贴 Cookie。
- `chrome.storage.local` 仅长期保存颜色顺序、搜索深度和满关注过滤选项。角色 ID、具体因子、双星级和因子优先级保存在 `chrome.storage.session`，刷新页面时可以恢复，浏览器会话结束后自动清空。
- 一键识别的原始文本、预览结果、累计待导入清单和撤销快照只保留在当前页面内存中，不写入扩展存储；收起再打开面板仍会保留，刷新或关闭网页后清空。
- 金技能和繁中名称映射均是随扩展打包的静态公开资料；运行时不会请求 BWIKI，也不会向其发送任何用户数据。
- 因子目录、角色目录和好友种马搜索均为只读用途；扩展不会关注玩家、修改账号资料或执行游戏内操作。
- 好友候选请求始终串行并间隔 350～500 毫秒；相同查询仅在当前页面内存中缓存 5 分钟，调整优先级后会复用候选并重新评分。用户也可勾选“本次强制刷新”绕过旧缓存。普通搜索结束后不冷却，一次选择至少 15 个因子时仅冷却 2 秒；遇到接口限流或风控提示时会停止搜索并延长冷却，不会持续重试。
- 安装前可直接审阅全部源码；仓库不包含远程加载的扩展代码。

完整说明见[隐私政策](./PRIVACY.md)。

## 已知限制

- 搜索依赖当前登录状态、吗哩吗哩网页结构和公开网页接口；其中任一项变化都可能导致暂时不可用。
- 为控制请求量，自动发现最多使用当前最高优先的 12 个具体因子；所有已选因子仍会参与最终评分。
- 吗哩吗哩单次搜索最多接受 3 个绿因子；扩展会在生成每组查询时自动截取该组优先级最高的 3 个，不限制本地选择和最终评分数量。
- 当前对单个好友种马排名；角色条件用于限定好友种马本体，尚未计算自有种马与七角色组合相性。
- 结果质量取决于接口当前可返回的数据、搜索深度和好友池，并不保证找到全服最优解。

## 开发与测试

本项目没有构建步骤。修改源码后，在仓库根目录运行：

```powershell
node --test
node --check ranking.js
node --check gold-skill-map.js
node --check background.js
node --check page-bridge.js
node --check request-guard.js
node --check content.js
```

也可以直接在浏览器中打开 `tests/harness.html` 做静态界面检查。修改扩展后，需要在扩展管理页点击“重新加载”，再刷新吗哩吗哩页面。

## 项目结构

| 路径 | 作用 |
| --- | --- |
| `manifest.json` | Manifest V3 权限、站点范围与脚本入口 |
| `background.js` | 使用 Manifest V3 会话存储代理角色和因子条件；不常驻、不访问网络 |
| `page-bridge.js` | 在页面上下文中调用官方网页接口 |
| `ranking.js` | 查询规划、因子整理与评分排序 |
| `gold-skill-map.js` | BWIKI 简中金技能到下位白技能的本地映射 |
| `traditional-name-map.js` | BWIKI 繁中因子/金技能名到简中正式名称的本地映射 |
| `factor-recognizer.js` | 本地文本规范化、因子分词、简称与星级识别 |
| `request-guard.js` | 候选查询的串行限速、短期缓存、冷却与有限退避重试 |
| `content.js` | 面板 UI、交互、偏好存储与搜索流程 |
| `tests/` | Node.js 单元测试与浏览器静态检查页 |
| `reverse-notes/` | 接口字段和行为的复核记录 |
| `scripts/build-release.ps1` | 生成并校验供 GitHub Releases 分发的安装 ZIP |
